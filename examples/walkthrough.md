# 一次完整的使用记录

> 这个文件记录一次真实场景下的完整走法，方便你对照自己的情况。
> 场景：一个做了两周的老项目，从没整理过文档，旧窗口上下文快满了。

---

## 0. 触发

你在旧窗口里说：

```
/changrenwu 我这个窗口快满了，项目也一直没整理过文档，不知道该怎么交接
```

---

## 1. 技能先问你三个问题

> **Q1｜这个项目有「环境」吗？**
> 有：工作区里能找到 `AGENTS.md` / `PROGRESS.md` / `FEATURES.md` / `prompts/resume.md` 中至少 2 个
> 没有或不确定：只有零散笔记
> 只有手写交接文件：有 `PROJECT_STATE.md` 之类，但没有上面那套
>
> **Q2｜当前这个窗口手上有「做到一半的活」吗？**
> 有 / 没有 / 撞车了
>
> **Q3｜你这次想干什么？**
> 换窗口 / 继续做 / 开新任务 / 救火

你选：**Q1 没有或不确定 · Q2 没有 · Q3 换窗口**

---

## 2. 技能的判定

> **你属于情况 1（首次接管），依据是：你说"项目一直没整理过文档"（Q1 = 无环境），
> 手头的活告一段落（Q2 = 无半成品），这次是要换窗口（Q3）。
> 如果判断错了，告诉我改。**

（这一步很关键——你随时可以纠正它。）

---

## 3. 旧窗口：先保命（P1）

**发：**

```
上下文快满了，现在做收尾交接。不要再开始任何新工作，不要优化代码，
不要"顺便补个测试"。

【第 1 步：保命】
1. git status，贴完整结果
2. 有未提交改动：git add -A && git commit -m "wip: checkpoint before context reset"
3. 没 git 就告诉我，先别动
...
```

**它会回：**

```
【第 1 步】
git status 结果：
  Changes not staged for commit:
    modified:   src/routes/orders.js
    modified:   src/db/schema.sql
  Untracked files:
    src/routes/export.js
已执行：git add -A && git commit -m "wip: checkpoint before context reset"
新 commit: 8f3a2c1

【第 2 步】
已创建 PROGRESS.md ...

【第 3 步】交接摘要（12 行）
...
```

**做完立刻关掉这个窗口。**

> 🗣 **为什么第一步是保命而不是"你把项目总结一下"**：
> 旧窗口只剩最后一口气。总结要读几十个文件、跑测试、翻 git 历史——这个过程本身就能把它撑爆。
> 一旦撑爆，那三个未提交的文件（`orders.js`、`schema.sql`、`export.js`）就永远留在工作区里，下次谁也不知道它们改到哪了。
> **先落盘，后写字。顺序反了就是事故。**

---

## 4. 新窗口：考古（P2）

**开一个新窗口，发：**

```
你接手一个已存在但我没理清状态的项目。这一轮只读，禁止改任何业务代码。
任务不是回忆过去，是测绘现在。

1.【Git】...
2.【状态文件】...
3.【测试】...
4.【结构】...
5.【功能反推】...
6.【缺口】...

先只给我看这 6 部分，不要写文件。
```

**它会回（节选）：**

```
【1. Git】有 .git，最近 10 个 commit：
  8f3a2c1 wip: checkpoint before context reset
  c41d7e2 feat: 订单列表分页
  ...

【3. 测试】找到 npm test，实际运行结果：
  Tests: 2 failed, 14 passed, 16 total
  失败 1：tests/orders.test.js:88 —— expect(200) received 500
  失败 2：tests/export.test.js:12 —— Cannot find module '../src/routes/export'

【5. 功能反推】
  - 订单列表 ✓（src/routes/orders.js + tests/orders.test.js）
  - 订单导出 ✗（src/routes/export.js 有文件，没测试，没挂载到路由）

【6. 缺口】
  - 为什么用原生 SQL 而不是 ORM？无记录
  - src/legacy/ 整个目录没有引用、没有测试，疑似废弃
```

> 🗣 **为什么审计放新窗口**：
> 新窗口是白纸，空间充裕，正好干重活。而且它没有旧窗口的偏见——
> 旧窗口会"记得"自己做过什么，倾向于美化；新窗口只能看证据。
>
> **证据和记忆冲突时，永远信证据。**

---

## 5. 新窗口：补建（P3）

**看完考古结果，确认无误后发：**

```
根据测绘结果补建环境，写在仓库根目录：
1. AGENTS.md — 构建/测试/规范/已知的坑（只写能验证的）
2. FEATURES.md — 功能清单，已实现打 [x] 并标 commit
3. PROGRESS.md — 状态：补建基线完成；下一步：<第一个未完成功能>
4. KNOWN_UNKNOWNS.md — 第 6 步的缺口原样写入
5. prompts/resume.md — 接手流程模板

然后：检查 .gitignore → git add -A →
git commit -m "chore: retrofit agent environment baseline"
```

**它会回：**

```
已创建 5 个文件。
.gitignore 补充了 node_modules/、.env、data/
新 commit: b9e4f10

下一步第一步：修 tests/export.test.js:12 的模块路径，然后给 export.js 挂路由。
还缺的信息：订单导出的目标格式（CSV？Excel？）—— 无人知晓，已写入 KNOWN_UNKNOWNS.md
```

> 🗣 **为什么补的要是"现状"而不是"历史"**：
> 过去为什么这么选，已经找不回来了。硬要还原就会变成编故事。
> 编出来的理由比"不知道"更糟——下一个 AI 会基于假前提大干一场。
>
> **承认损失，把"现在是什么样"写清楚，从这一刻起算 Day 0。**

---

## 6. 以后每次新窗口，只说一句

```
读 prompts/resume.md，按流程执行。先从第 0 步侦察开始，不要写代码。
```

它会：

1. 读 `AGENTS.md`、`PROGRESS.md`、`FEATURES.md`
2. 跑 `git status` / `git log` / 测试，核对真实状态
3. 回答四个问题（目标 / 进度 / 下一项 / 矛盾）
4. 停下，等你确认

你回一句：

```
确认。现在只做 Q3 指定的那一项。先写测试确认红 → 实现 → 全绿 → 更新 PROGRESS.md → commit。做完停。
```

---

## 7. 这一轮踩的坑（复盘）

| 坑 | 后果 | 下次怎么办 |
|---|---|---|
| 第一次想直接在旧窗口做总结 | 差点把 3 个未提交文件弄丢 | 旧窗口只做保命三件事 |
| 旧窗口摘要里写"订单导出已完成" | 实际没挂路由、没测试 | 摘要必须在考古之后对账 |
| 一开始没跑测试 | 不知道有 2 个红 | 考古第 3 部分必跑 |

---

## 8. 一句话总结这个流程

```
旧窗口：保命 → 留痕 → 一句话摘要 → 关
新窗口：考古 → 补建 → 基线提交 → 从此一句话开工
```

**你的项目从"靠记忆"变成了"靠文件"。后者不会忘。**
