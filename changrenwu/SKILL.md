# Agent 长任务：双阶段工作流与交接手册（CMD-06 · 长任务）

## 何时使用

用户在做一件跨多轮、跨窗口的工程任务，出现以下任一情况：

- 上下文窗口快满，要换窗口
- 新窗口要接手一个进行中的项目
- 不确定 agent 是否忘了前面的事
- 两个窗口同时改同一处，撞车了
- 不知道现在该发什么提示词

## 输入

用户的处境描述。**允许用户说不清**——本技能第一条就是问清楚。

## 核心原理（一句话）

> **把大模型当 CPU，把文件系统当内存和硬盘。**
> 上下文只装「这一轮要用的操作数」，其余全部外挂到硬盘，靠 git + 测试 + 文档做寻址。

三大原则：**环境即记忆**、**串行优于并行**、**测试驱动**。

---

## 执行规则

### 第 0 步：判定情况（禁止跳过，禁止猜）

**必须先问清楚，再给方案。** 用 `ask_user` 一次问三个问题，每个选项都带识别信号，让用户对号入座：

**Q1｜这个项目有「环境」吗？**
- **有**：工作区里能找到 `AGENTS.md` / `PROGRESS.md` / `FEATURES.md` / `prompts/resume.md` 中至少 2 个
- **没有或不确定**：只有零散笔记，或者你从没整理过
- **只有手写交接文件**：有 `.handoff/PROJECT_STATE.md` 之类，但没有上面那套

**Q2｜当前这个窗口手上有「做到一半的活」吗？**
- **有**：某个功能改了一半、测试还红着、任务没做完
- **没有**：手头的活已收尾，或本来就是空的
- **撞车了**：两个窗口在改同一处

**Q3｜你这次想干什么？**
- **换窗口**（这个快满了，要交接）
- **继续做**（就是正常推进下一项）
- **开新任务**（清单里没有的新需求）
- **救火**（怀疑它忘了 / 已经出问题）

**判定表**（三问组合 → 情况）：

| 环境 | 半成品 | 目的 | 情况 |
|---|---|---|---|
| 没有 / 只有手写交接 | 任意 | 换窗口 / 继续 | **情况 1 首次接管** |
| 有 | 无 | 换窗口 / 继续 | **情况 2 常规推进** |
| 有 | 有 | 换窗口 | **情况 4 半成品交接** |
| 有 | 任意 | 开新任务 | **情况 5 新需求立项** |
| 没有 | 有 | 换窗口 | **情况 1**（交接时带断点五要素） |
| 任意 | 撞车 | 救火 | **情况 6a 并行冲突** |
| 任意 | 任意 | 怀疑忘了 | **情况 6b 体检** |

判完必须明说一句：

> **「你属于情况 X，因为（引用用户回答里的具体事实）。」**

让用户能当场纠正你。**如果三问答案互相矛盾**（比如"有环境"但说不出文件在哪），先追问一句核实，不要硬判。

### 第 1 步：按情况给步骤

跳到对应小节。每一步都必须给：**可复制提示词 + 大白话解释**。

### 第 2 步：收尾提醒

给本次最容易踩的 1~3 个坑，**最重要的那条加粗**。

---

## 输出结构（每次执行都按这 5 块输出）

1. **判定**：你属于情况 X，依据是……
2. **步骤清单**：2~4 步，一行一步
3. **逐步骤**：
   - 📋 可复制提示词（代码块，原样可粘贴）
   - 🗣 大白话：这一步在干什么，为什么不能省、不能换顺序
4. **双阶段能带来什么**（首次执行时详细讲，后续一句话带过）
5. **注意**：本次最容易踩的坑

## 情况库

### 情况 1 · 首次接管（没有环境）

**识别信号**：说不出 `AGENTS.md` / `PROGRESS.md` 在哪；不知道 git 有没有提交；不知道测试跑不跑得动；只有零散的会话记录或手写笔记。

**步骤**

1. 旧窗口发 **P1**（保命三件事）→ 做完立刻关
2. 新窗口发 **P2**（考古，只读）
3. 新窗口发 **P3**（补建 5 个文件 + 基线 commit）
4. 以后每个新窗口发 **P4**（一句话）

**大白话解释**

- **为什么先保命不先审计**：旧窗口只剩最后一口气。审计要读几十个文件、跑测试、翻 git 历史，这个过程本身就能把剩下的上下文撑爆。结果往往是**审计做到一半窗口崩了，连做好的工作都没 commit**。所以旧窗口只干一件不可替代的事——**把成果落盘**。
- **为什么审计放新窗口**：新窗口是白纸，空间充裕，正好干重活。而且它没有旧窗口的偏见，能独立判断"文档说的和代码做的是不是一回事"。
- **为什么补建的是"现状"不是"历史"**：过去每一步为什么这么选，已经找不回来了。硬要还原就会变成编故事。**承认损失，把"现在是什么样"写清楚，从这一刻起算 Day 0。**

**注意**

- **旧窗口禁止做任何"优化、重构、补测试"**，那是最容易把成果弄丢的操作。
- 补建阶段只读，不许改业务代码——否则基线就被污染了。
- 过去的缺口写进 `KNOWN_UNKNOWNS.md`，**不要编理由**。编出来的比没有更糟：下一个 agent 会基于假前提大干一场。

---

### 情况 2 · 常规推进（有环境，接着做）

**识别信号**：`FEATURES.md` 里还有没做完的项；这次就是接着往后做；没有撞车。

**步骤**

1. 新窗口发 **P4**
2. 等它侦察完、复述完 → 回答 **「确认。现在只做 Q3 那一项……」**
3. 它做完 → 你说 **「交接」** → 关窗口

**大白话解释**

- **为什么只需要一句话**：环境已经建好了，真相都在文件里。新窗口读文件就等于"继承了记忆"，你不需要再讲一遍项目背景——**这就是双阶段最省人的地方**。
- **为什么每轮都要清空而不是一直聊下去**：每轮都是"空杯装一次水，倒掉再装"。杯子不溢，成本就是常数；一直往里倒，早晚溢出，而且是**在你没注意的时候**溢出。

**注意**

- 侦察轮（P4）**不给它开工权限**。先复述、你确认，再动手——这一步能拦住"它理解错了但已经大干一场"。
- 它答完 Q4（矛盾/缺失）时，**认真看**：那往往就是环境开始漂移的信号。

---

### 情况 3 · 常规交接（有环境，窗口快满）

**识别信号**：上下文用到 60% 以上；手头的功能做完了或告一段落；要换个窗口继续。

**步骤**

1. 旧窗口发 **P1-轻量版**（更新文件 + commit，3~5 分钟）
2. 新窗口发 **P4**

**大白话解释**

- **为什么比情况 1 便宜十倍**：环境建好之后，交接从"考古"降级成"更新"。上一次要重新测绘整个项目，这一次只要把进度补进 `PROGRESS.md` 就行。
- **摘要为什么退化成可选**：文件里已经有了大部分信息，摘要只写"文件装不下的"——风险、被否决的方案、需要人拍板的决策。

**注意**

- **别等窗口满了才交接**。60% 就该准备了，因为交接动作本身也要花上下文。
- 交接摘要里最容易吹牛的是"已完成"，**必须用 `git log` 核对**。

---

### 情况 4 · 半成品交接（做到一半要换窗口）

**识别信号**：有个功能改了一半；测试可能还红着；上下文快满了。

**步骤**

1. 旧窗口先发 **P5**（判断：收尾还是立刻交接）
2. 按判断结果：
   - 剩 ≤2 步且纯执行 → 先收尾，再走第 3 步
   - 剩下要设计决策 / 测试跑不动 → 直接走第 3 步
3. 旧窗口发 **P6**（P1 + 断点五要素）
4. 新窗口发 **P7**（续接，只读 5 问）

**大白话解释**

- **为什么要先判断收尾还是交接**：收尾能把状态变成"全绿 + 可交接"，价值很大；但硬撑一个需要设计决策的任务，产出的东西大概率要在新窗口推翻重做，等于白烧 token。
- **为什么半成品要写"断点五要素"**：半成品最怕的不是没做完，是**"做到哪了"没写下来**。下一个窗口看到"正在做搜索"，它会从零开始猜——猜错方向就白干半天。

**注意**

- 断点第 3 条必须写**测试红在哪一行**，不能只写"有测试失败"。
- 断点第 5 条（需要人拍板的设计决策）**不要省**，那是你作为人类的判断权。

---

### 情况 5 · 新需求立项（清单里没有的新东西）

**识别信号**：你想做的事 `FEATURES.md` 里查不到；需要先登记再开工。

**步骤**

1. 新窗口发 **P4**（先侦察，不开工）
2. 发 **P8**（需求转译）→ 拿到候选验收标准 → **你删改拍板**
3. 让它把定稿写进 `FEATURES.md`（或先写 `prompts/inbox.md` 再转正）
4. 发 **「确认。现在只做 F0X 这一项……」**

**大白话解释**

- **为什么不登记就等于没发生**：这个窗口吭哧吭哧做完了，下个窗口读 `resume.md` 时根本不知道有这回事——**任务做完了，但环境里没有它的位置**。双阶段是靠清单驱动的，清单外的活等于幽灵工作。
- **为什么验收标准必须你拍板**：让 AI 自己定义"什么叫做完"，它会定义成最容易达成的那个版本。"搜索功能可正常使用"就是典型的自我放水。

**注意**

- 需求必须拆成**能独立验收**的项。一个笼统的"做个搜索功能"会变成无底洞；拆成"按标题搜 / 按标签筛 / 分页"才做得完。
- 验收标准必须能写成一行测试断言。写不成 → 太模糊，退回重写。

---

### 情况 6a · 并行冲突（撞车了）

**识别信号**：两个窗口改了同一处；或者两边 AI 反馈"我改了 X"而 X 已经被另一边改过。

**步骤**

1. 两个窗口都发 **冻结指令**（停止写入）
2. 选定唯一写者（看测试谁更绿、改动谁更小）
3. 盘点：`git status` / `git diff --stat` / `git branch -a` / `git stash list` / `git log --oneline --graph -15`
4. 冲突分三类：文件级互斥（好办）/ 同文件不同区域（要跑测试）/ 不同文件同一接口（**最危险，git 不报**）
5. 串行重放：先保住一边全绿 → 另一边一次一个 commit 重放 → 每重放一次跑一次测试
6. 补契约：把争执的接口写进 `AGENTS.md`，commit
7. 理不清就开第三个只读窗口，发 **P12**（仲裁）

**大白话解释**

- **为什么绝不能让两个撞车的窗口互相协商**：它们都基于**过期的世界模型**在做判断，让它们对话只会互相说服、越修越乱。仲裁必须来自"干净状态"——要么你人工，要么第三个只读窗口。
- **为什么"不同文件同一接口"最危险**：git 会显示零冲突，一跑测试全红。这是并行的真正杀手。

**注意**

- **冲突的解决不能由冲突的双方来做。**
- 合并完第一件事是把契约写进文档，否则下次还会撞。

---

### 情况 6b · 怀疑它忘了

**识别信号**（出现任意一条）：重复问你已经回答过的事 / 引用不存在的文件或函数 / 又提出你否决过的方案 / 说"已完成"但 `git status` 有脏文件 / 开始改测试或注释断言 / 忘记最初约束 / 回复变短变套路化。

**步骤**

1. 发 **P10**（体检 5 问）
2. 任何一题答错或含糊 → **直接交接**，不要试图"提醒它"
3. 用 `git log` 核对它说的"已完成"

**大白话解释**

- **为什么不能靠问"你记得吗"判断**：它会自信地编。**你无法可靠地问出它忘没忘**，只能靠行为症状 + 外部命令验证。
- **为什么出现症状就直接交接**：劣化的上下文会污染后续每一个判断。你花 20 分钟纠正它，它下一轮又漂走。**修复成本 > 重开成本。**

**注意**

- 区分"真遗忘"（文件里有，它不记得）和"从未知道"（文件里也没有）——后者是环境缺失，清空救不了，得补文档。

## 提示词库（原样可复制）

### P1 · 旧窗口保命交接

```
上下文快满了，现在做收尾交接。不要再开始任何新工作，不要优化代码，
不要"顺便补个测试"。

【第 1 步：保命】
1. git status，贴完整结果
2. 有未提交改动：git add -A && git commit -m "wip: checkpoint before context reset"
3. 没 git 就告诉我，先别动

【第 2 步：留最小痕迹】
创建/覆盖 PROGRESS.md，只写 6 节，每节 ≤5 行：
- 项目目标（一句话）
- 已完成（功能名 + commit hash，对不上的标"未提交"）
- 进行中（当前任务 + 做到哪一步）
- 下一步第一步（具体到能直接执行）
- 已知问题（红着的测试）
- 试过但失败的方向（简述 + 为什么放弃）

【第 3 步：交接摘要】
输出 ≤15 行给下一个会话的摘要：目标 / 已完成 / 卡在哪 / 下一步 / 最大风险

⚠️ 禁止：重构、补测试、写文档、整理目录
```

### P1-轻量版 · 有环境时的交接（3~5 分钟）

```
上下文快满了，做收尾交接。不要开始新工作，不要优化代码。

1. git status；有未提交就 git add -A && git commit -m "wip: checkpoint before context reset"
2. 更新 PROGRESS.md 这四节（其他节不动）：
   - 当前状态：正在做哪一项、做到哪一步
   - 已完成：本轮新增的项 + commit hash
   - 断点：下一步第一个动作（具体到文件/函数/断言）
   - 已知问题：红着的测试、没解决的坑
3. 跑一遍测试，把真实结果（命令 + 通过数 + 失败数）写进 PROGRESS.md
4. 最后回答：有没有什么信息是 PROGRESS.md 装不下、但下个会话必须知道的？
   有就 ≤10 行写出来；没有就回答"无"。
```

### P2 · 新窗口考古（只读）

```
你接手一个已存在但我没理清状态的项目。这一轮只读，禁止改任何业务代码。
任务不是回忆过去，是测绘现在。

1.【Git】有 .git 吗？git log --oneline -10、git status、git branch -a
2.【状态文件】根目录所有文件；README/PROGRESS/TODO/AGENTS/docs/；
   逐个判断：有内容吗？和代码对得上吗？
3.【测试】找测试命令，实际跑一次，原样贴：命令/总数/通过/失败/原因
4.【结构】顶层目录、入口文件、主要依赖；标出核心 vs 遗留
5.【功能反推】从代码和测试反推"已实现什么"，每项标证据
6.【缺口】哪些信息无法从代码推断（不要编）

先只给我看这 6 部分，不要写文件。
```

### P3 · 新窗口补建

```
根据测绘结果补建环境，写在仓库根目录：
1. AGENTS.md — 构建/测试/规范/已知的坑（只写能验证的）
2. FEATURES.md — 功能清单，已实现打 [x] 并标 commit
3. PROGRESS.md — 状态：补建基线完成；下一步：<第一个未完成功能>
4. KNOWN_UNKNOWNS.md — 第 6 步的缺口原样写入
5. prompts/resume.md — 接手流程模板

然后：检查 .gitignore → git add -A →
git commit -m "chore: retrofit agent environment baseline"
告诉我：commit hash、「下一步第一步」、「还缺什么信息」
不要改任何业务代码。
```

### P4 · 以后每个新窗口（一句话）

```
读 prompts/resume.md，按流程执行。先从第 0 步侦察开始，不要写代码。
```

### P5 · 判断「收尾还是交接」

```
停一下，先回答三个问题，不要开始新工作：
1. 当前任务还剩几步？具体列出来
2. 剩下步骤里有没有需要设计决策的（而非纯执行）？
3. 现在跑测试，退出码是多少？贴输出
```

### P6 · 半成品交接（P1 + 断点五要素）

在 P1 的第 2 步里补：

```
【断点五要素】
1. 任务目标 + 验收标准（照抄原文，不要改写）
2. 已改过哪些文件（完整路径清单）
3. 测试状态：哪几个红、红在哪个文件哪行、报什么错
4. 下一步第一个动作：具体到打开哪个文件、改哪个函数、加什么断言
5. 有没有做了一半、需要人拍板的设计决策
```

### P7 · 新窗口续接半成品（只读）

```
你接手一个做到一半的任务。这一轮只读，禁止改代码。
1. 读 AGENTS.md、PROGRESS.md、FEATURES.md
2. git status、git log --oneline -5
3. git diff HEAD~1 --stat
4. 跑测试，记录真实结果

只回答五问，答完停下：
Q1 当前任务目标和验收标准（照抄原文）
Q2 已做到哪一步？哪些文件被改了？
Q3 测试什么状态？红在哪？
Q4 下一步第一个具体动作是什么？
Q5 有信息缺失或矛盾吗？
```

### P8 · 需求转译（写验收标准前用）

```
我有个新需求，帮我做"需求转译"，不要写代码。
【需求原文】<一句话>

输出：
```

## 双阶段架构：是什么 + 带来什么

**阶段一 · 开荒（一次性，1~2 小时）**
不产功能代码，产「环境契约」：`AGENTS.md`（怎么干活）、`FEATURES.md`（要做什么）、`PROGRESS.md`（到哪了）、测试框架、一条全量检查命令、基线 commit。

**阶段二 · 循环（每轮 15~40 分钟，一轮一个功能）**

```
读环境 → 取一个功能 → 先写测试确认红 → 实现 → 全绿
→ 更新 PROGRESS.md → commit → 清空上下文
```

**六个好处**

| 好处 | 一句话解释 |
|---|---|
| 成本可控 | 每轮 token 是 O(1)，不是 O(n)；40 轮任务差 40 倍 |
| 可恢复 | 任意时刻崩溃，新会话读 5 个文件就能接手 |
| 可归因 | 一轮只有一个功能一次 commit，出问题能定位到具体一轮 |
| 不腐化 | 每轮上下文都是新鲜的，不受 context rot 影响 |
| 人只做判断 | 你不用反复讲背景，只做"确认/拍板" |
| 知识变资产 | 项目知识沉淀在文件里，不随窗口消失 |

**六条注意事项**

1. **阶段一偷懒 = 阶段二十倍偿还**（失败案例第一大原因）
2. **环境文档过期比没有更糟**——agent 会基于错误状态高效跑偏
3. **测试改弱 = 验收器失效**，禁止为通过测试而改测试
4. **同一工作区只能有一个写窗口**
5. **交接摘要永远后发**（先独立观察，再拿二手信息对账）
6. **验收标准必须人拍板**，AI 只起草

## 约束

- **先判定，后给方案。** 没判定出情况之前，不许直接甩提示词。
- **每个步骤必须配大白话解释**，只给提示词不给理由，用户学不会。
- 提示词必须**原样可复制**，不要包在需要用户自己填的说明里（除了明确的占位符）。
- 用户的情况可能同时命中多个信号 → 按**最危险的那个**处理（撞车 > 半成品 > 无环境）。
- 解释原理时先查 `references/术语表.md`，术语要准。
